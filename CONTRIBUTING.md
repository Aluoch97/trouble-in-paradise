# Working on Trouble in Paradise together

## The one rule that saves the most pain

**Two people should never edit the same scene file (`.tscn`) at the same time.** Godot scene files merge badly. Before you start on a scene, say so in the group chat or claim it in a GitHub Issue. Code (`.gd`) and dialogue (`.json`) files merge fine.

## Day-to-day flow

1. **Get the latest:** `git pull` (or **Fetch origin → Pull** in GitHub Desktop).
2. **Make a branch** named for what you're doing: `mission-3-scene-two`, `jessica-character`, `radio-tracks`.
3. **Work, then play-test** with F5. Make sure mission 2 still plays start to finish.
4. **Commit** small, clear steps: "Add Jessica's car", not "stuff".
5. **Push and open a Pull Request** into `main`. GitHub runs the automated playthrough on it. Someone else looks it over before it's merged.

Never push straight to `main`. Nick (repo owner) can turn that into a hard rule under **Settings → Branches → Add branch protection rule**.

If you've never used Git, install **GitHub Desktop** (<https://desktop.github.com>). It does all of the above with buttons.

## Commit these, never these

| Commit | Don't commit |
| --- | --- |
| `.gd`, `.tscn`, `.tres`, `.json`, `.gdshader` | `game/.godot/` (Godot's cache; it rebuilds) |
| `.import` and `.uid` files next to your assets | Exported builds (`.exe`, `.pck`, `.apk`). Share those under **Releases**. |
| Art, models, fonts, sounds, songs | Your own editor settings |

The `.gitignore` already handles the "don't" column.

GitHub rejects single files over 100 MB. Songs as `.ogg` or `.mp3` are fine; WAV masters or huge `.blend` files are not. Keep those in Google Drive and commit the exported version.

## Who does what

| Role | Works in | Good first tasks |
| --- | --- | --- |
| **Writers** | `docs/design-doc.md`, `game/data/dialogue/` | Write mission 3 (*Scene II: Now*) dialogue as a new JSON file in the same format |
| **Level designers** | `game/scenes/world/town.tscn` | Build the Quarry. Move the mission markers under `Town/Markers` to re-stage a scene. |

## How the code is laid out

| Script | What it does |
| --- | --- |
| `autoload/game_state.gd` | Global `Game`: Trust meters, Drama meter, story flags |
| `characters/player.gd` | Nick on foot: movement, getting in and out of cars, talking |
| `characters/npc.gd` | Story characters: follow, walk to a spot, can be talked to |
| `vehicles/car.gd` | Driving physics, handbrake, crashes |
| `camera/camera_rig.gd` | Third-person camera and cutscene angles |
| `missions/mission_welcome_to_paradise.gd` | Mission 2, start to finish. Copy it to start a new mission. |
| `missions/checkpoint.gd` | Pink mission markers |
| `ui/hud.gd`, `ui/radar.gd` | Everything on screen |
| `world/` | Town layout, traffic, pedestrians, day/night |
| `audio/radio.gd` | SA NU FM |

### Rebuilding the town from code

`town.tscn` was generated by `game/tools/generate_scenes.gd` from the grid in `world/town_layout.gd`. Normally you just edit `town.tscn` in the editor. If you change the grid and want to regenerate:

```
godot --headless --path game res://tools/generate_scenes.tscn -- --town-only
```

That **overwrites** `town.tscn`, so anything placed by hand in the editor is lost. Agree on it with the level designers first.
